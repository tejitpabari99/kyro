## Must-fix

- [Bug Hunter, also flagged by Architect] `src/features/workout/NoteEditSheet.tsx` (Sheet body,
  the `flex: 1` `View` wrapping `TextInput` + the new `ScreenFooter` sibling after it) — the
  diff pulls `ScreenFooter` **out** of the `flex: 1` `View` that wraps the `TextInput` and makes
  it a sibling rendered after that `View` closes, instead of nesting it as the `View`'s last
  child (the pattern used correctly elsewhere in this same diff, e.g. `FolderNameSheet.tsx`).
  Confirmed against the diff and against `git show 29b807e:.../NoteEditSheet.tsx` (pre-diff
  state, where the Save `Button` was the last child *inside* the same `flex:1` `View`, with no
  gap). Because the `View` is the only flex-grow sibling among `[SheetHeader, View,
  ScreenFooter]`, it absorbs all remaining vertical space in the sheet; `TextInput` packs to the
  top of it (default `justifyContent: 'flex-start'`), leaving a dead gap between the note field
  and the Save button that grows with less note text — the exact "sticky-by-accident" failure
  mode `ScreenFooter.tsx`'s own doc comment calls out as the pattern to avoid, just manifesting
  through a `flex:1` `View` instead of a `flex:1` `ScrollView`. This is directly contrary to the
  PRD's single most emphasized `ScreenFooter` placement contract (§4.3), and no test in this diff
  caught it because no test targets `NoteEditSheet`'s structure. Fix: nest `ScreenFooter` inside
  the `flex:1` `View` as its last child (matches `FolderNameSheet.tsx`'s pattern), or drop
  `flex: 1` from the `View` since it serves no scroll/expand purpose here.
